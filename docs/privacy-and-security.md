# Privacy and Security

## Data minimisation

Retrieve only information needed for the churn assessment. Avoid unrelated email, unnecessary attachments, sensitive personal data and complete mailbox histories.

## Evidence handling

Use concise evidence summaries rather than full message content. Direct customer statements should carry more weight than internal speculation, but should still be represented only to the extent needed to support the recommendation.

## Access

Use least-privilege connections and environment-specific configuration. Production recipients, connection references and identifiers belong in private deployment configuration, not source control.

## Logging

Public logs and examples must not contain customer names, domains, contact names, email content, ARR, renewal dates, internal notes, tenant identifiers or generated production reports.

## Screenshots

Publish only cropped, sanitised screenshots showing generic workflow structure. Do not expose browser chrome, environment names, URLs, profiles, connection configuration, run history or action outputs.
